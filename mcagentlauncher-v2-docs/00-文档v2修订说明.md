# MCagentlauncher 文档 v2 修订说明

日期：2026-07-08  
修订原因：明确 GitHub–Vercel–Supabase 链路边界，并升级为完整的 **GitHub–Vercel–Supabase–MCAgent–Desktop** 技术链路。

---

## 1. 本次修订的核心变化

旧表述容易让 Codex 误解为：

```text
GitHub–Vercel–Supabase = 项目的完整技术后端
```

v2 文档明确改为：

```text
GitHub–Vercel–Supabase–MCAgent–Desktop
```

也就是：

```text
GitHub
代码、协作、CI、Release

Vercel
官网、文档、Web 控制台、PR Preview

Supabase
社区数据、Auth、规则库、别名库、匿名案例、审核状态

MCAgent Inference Endpoint
独立、可替换、可自托管的 AI 推理服务

Desktop Local Executor
桌面端本地执行：下载、校验、安装、启动、回滚
```

---

## 2. 必须明确的边界

### GitHub 做什么

- 代码托管
- Issue / PR
- Actions CI
- Release
- 项目看板
- 贡献协作

### Vercel 做什么

- 官网
- 文档站
- Roadmap
- Web 控制台
- 规则/别名贡献入口
- PR Preview
- 静态或轻量 Web API

### Vercel 不做什么

- 不做 GPU 模型推理
- 不做 Minecraft 资源镜像
- 不做长时间安装任务
- 不做用户本地文件操作

### Supabase 做什么

- Postgres
- Auth
- Storage
- Edge Functions
- 社区别名库
- 社区规则库
- 匿名案例库
- 模型评测样本索引
- 审核状态

### Supabase 不做什么

- 不做 GPU 推理
- 不做 Minecraft 资源分发
- 不直接操作用户本地实例
- 不保存未脱敏完整日志

### MCAgent Endpoint 做什么

- parse_intent
- plan_resources
- explain_plan
- 后续 diagnose_log
- 后续 repair_plan

### Desktop Local Executor 做什么

- 本地实例创建
- Minecraft/Fabric 安装
- 资源下载
- Hash 校验
- 配置写入
- 试启动
- 日志读取
- 快照与回滚

---

## 3. 给 Codex 的明确要求

Codex 后续实现时不得把以下职责混淆：

1. 不要把模型推理写进 Vercel Serverless 作为长期架构。
2. 不要把 Supabase 当作 Minecraft 资源镜像源。
3. 不要让 MCAgent 直接执行文件操作。
4. 不要让 Web 控制台替代桌面端本地执行器。
5. 不要默认上传完整日志到 Supabase。
6. 不要把商业大模型作为 v0.1 的必要运行条件。
7. 所有安装动作必须由 Desktop Local Executor 执行。
8. 所有资源选择必须经过 Rule Engine 校验。
