# M17 Controlled Workspace Transaction Foundation Review

## Review Status

M17 is verified and pushed on `codex/m17-controlled-workspace` at feature commit `c9a59f89d858ccf1ad52e41f8021c52e8198dd9d`. Draft PR #12 targets `main` and remains unmerged. This work crosses only the DQ-001, DQ-002, and DQ-007 minimum filesystem gate. It is not a playable release and does not approve any later gate.

## Approved Scope

Desktop may create a fixed application-managed synthetic test workspace beneath Tauri's application-data boundary, persist versioned manifest and transaction records, simulate commit/interruption/recovery/rollback, and remove only the current transaction's exact synthetic marker after explicit confirmation.

## Filesystem Operations Introduced

The single approved runtime module creates controlled directories, creates and synchronizes new fixed-name files, publishes them by same-directory rename, reads bounded controlled records and directory entries, and removes one exact regular test-marker file. Production code never recursively deletes a directory. No command accepts a root, path, filename, URL, executable, or environment record.

## Containment Model

- Tauri supplies the application-data root; the executor appends a fixed controlled-root name.
- Workspace and transaction inputs are lowercase opaque identifiers only.
- Absolute paths, `/` and `\\` separators, `.`/`..`, colons, Unicode, and Minecraft-like identities fail identifier validation.
- Existing ancestors are inspected and canonicalized; lexical and canonical containment are rechecked around filesystem operations where practical.
- Symlinks, Windows junctions, and all Windows reparse-point attributes fail closed.
- Existing unmarked roots/workspaces cannot be adopted.
- Hostile concurrent substitution and directory-entry synchronization remain platform limitations before broader mutation.

## Confirmation Model

The preview returns a digest token bound to schema version, policy version, fixed `app-managed` target class, workspace identity, unique transaction identity, strict `commit` or `interruption` operation, and fixed test-only purpose. Cross-operation, cross-workspace, cross-transaction, invalid-operation, and replay attempts are rejected. The token is not a credential, authentication proof, or later-capability approval.

## Manifest And Journal Model

The deterministic manifest and every journal event carry explicit schema versions. The manifest binds workspace, transaction, operation, fixed artifact path, ownership, and rollback strategy. Same-directory pending files use exclusive creation, file synchronization, and rename publication. Journal events are immutable, contiguous, canonical, state-checked, and SHA-256 chained.

The SHA-256 chain is tamper-evident corruption evidence only. It is not an authentication mechanism or trusted signature.

## Rollback Guarantees

Rollback validates the manifest and journal, revalidates containment, rejects every unknown artifact-directory entry, compares the full operation-bound current-transaction marker record, and removes only that regular file. Missing markers are idempotent. Mismatched, unknown, sibling, pre-existing, linked, or out-of-root data is never deleted.

## Interruption And Recovery Evidence

Tests cover interruption into `recovery_required`, transition to `rolling_back`, exact marker removal, terminal `rolled_back`, repeated recovery, committed no-op recovery, manifest corruption, journal gaps, sibling preservation, operation mismatch, and unknown-artifact refusal. Pending publication records fail closed for manual recovery.

## Test Isolation

Each filesystem test owns a uniquely prefixed OS-temp boundary guarded by `Drop`, so normal completion and panic unwinding remove it. A dedicated unwind test proves cleanup. The final review also scans for leftover prefixed directories; process termination that bypasses Rust destructors is not claimed as covered by RAII alone.

## Security Boundary

Filesystem authority exists only in the Desktop Tauri module. Web and MCAgent Server gain no command, path, or filesystem handle. No network download, installation, Java discovery/execution, shell/process execution, OAuth, Minecraft-directory access, real-instance mutation, telemetry, updater, sidecar, or commercial-model integration exists. `docs/platform-boundaries.md` and production dependency manifests are unchanged.

## Known Limitations And Closed Gates

The slice creates a synthetic marker only. It does not provide directory-entry fsync guarantees, authentication of journal digests, a hostile-concurrency proof, arbitrary crash-point initialization cleanup, real artifact verification, installation, or launch. `GATE-USER-PATH-01`, `GATE-NET-01`, `GATE-JAVA-01`, `GATE-OAUTH-01`, `GATE-PROC-01`, `GATE-DEP-01`, `GATE-UPDATER-01`, `GATE-SIDECAR-01`, `GATE-MC-DIR-01`, and `GATE-REL-01` remain closed.
