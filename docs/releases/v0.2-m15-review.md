## Architecture Summary

```text
Resource Resolver
  -> ResourceCandidate[]
  -> Compatibility Analysis Engine
  -> CompatibilityAnalysisResult
  -> compatibility-aware Resource Plan
```

Providers remain responsible only for normalized metadata. Analyzer policy is independent from provider clients and execution. Resource results and issues are stable across input order.

## Contracts

Shared contracts define compatibility status, severity, target, issues, per-resource checks, collection result, summary, selectors, target constraints, and explicit rules. Helpers provide target validation, status derivation, stable issue identity, deterministic sorting, and summary counts.

Existing Resolver issue contracts remain unchanged.

## Rule Model

Rules are explicit, version-controlled inputs with `ruleId`, type, normalized selectors, optional exact target constraints, severity, source, message, and enabled state. Supported types are conflict, requires, loader exclusion, Minecraft-version exclusion, and side constraint.

No rule uses resource display names. No built-in OptiFine/Sodium or other community conflict claim was added.

## Dependency Graph Behavior

- Required dependency matches project ID or slug, with version ID as secondary identity.
- Missing or identity-less required dependencies are blockers.
- Unverifiable dependency versions remain unknown warnings.
- Missing optional dependencies do not block.
- Provider-declared incompatible dependencies create explicit conflicts.
- Required cycles are canonicalized, reported once, and do not recurse indefinitely.

## Resolver Integration

`resolveAndAnalyzeMetadata` explicitly composes an existing `ResourceResolver` with the pure Analyzer and returns both results. It does not alter `MetadataResourceResolver.resolve` or enable network access. Offline requests remain zero-fetch.

## Plan Integration

`applyCompatibilityToResourcePlan` returns a cloned plan. Blockers become plan errors, high risk, and rejected status. Nonblocking concerns remain visible as warnings and raise risk to at least medium. Existing diagnostics are preserved, and the resource-plan schema is unchanged.

## Known Limitations

- Exact versions only; no semantic version ranges or fuzzy Minecraft-version equivalence.
- Rule fixtures are not a complete Minecraft compatibility knowledge base.
- Dependency cycle severity is warning pending richer install-order semantics.
- Analyzer does not query providers to fill missing dependencies.
- Analyzer does not repair or replace candidates.
- Compatibility wrapper is not yet exposed by Python MCAgent Server.
- Live resolver capability remains false.
- M16 remains Local Executor Architecture Design only.
